# Novel Writer: 小说长篇创作与工程化连贯性系统

本项目是一套专为 **20–50+ 章超长篇严肃小说创作** 设计的工程化智能辅助系统（完整支持中文与英文双语写作）。

系统最初由 [PenglongHuang/chinese-novelist-skill](https://github.com/PenglongHuang/chinese-novelist-skill) Fork 并演进而来。针对现代前沿大模型（Claude 3.5/3.7、GPT-4o、Gemini 2.5 等）强大的文学底蕴与叙事直觉，本项目进行了**彻底的工程减负与实战重构**，成功交付了 28 章全本全量产出的英文小说案例：**《The Transfer Kid》**。

---

## 演进哲学：强工程约束，零文风说教

### 为什么必须“减负”？
传统小说编写提示词和上游仓库倾向于不断叠加文风说教（例如堆砌“如何写隐喻”、“怎样用动作代替陈述”、“不是……而是……否定排比禁用”、“文风基准指纹与校准段落”、“多层多轮强制问答”等）。

然而在现实创作中：
1. **现代模型文风极佳**：前沿模型早已具备极为优秀的文学审美、潜台词把控与对话节拍，过度说教只会让模型输出变得僵化、教条和死板。
2. **长篇失控从不在文笔，而在工程状态管理**：AI 写长篇最容易溃败的地方在于——写到 10 章之后**前文遗忘、时序错乱、视角信息越界（角色未卜先知）、配角无端蒸发、上下文窗口超载崩溃**。

因此，本项目彻底剥离了冗长的文学写作说教与多余流程，将所有算力与规范聚焦于**“状态机控制与信息隔离”**。

## 六大核心硬规则 (Hard Guardrails)

系统严格执行由《The Transfer Kid》实战检验确立的六大硬规则：

```text
┌─────────────────────────────────────────────────────────────┐
│                    Novel Writer 核心护城河                   │
├──────────────────────────────┬──────────────────────────────┤
│ 1. 前文查阅禁令 (Notes-Only)  │ 严禁读旧文全文，只读 Notes 避爆上下文 │
│ 2. 桌面 EPUB 自动导出        │ 每章自检完毕直接推送到桌面 Reader     │
│ 3. 语言与字数硬锁定          │ 中文 3000-5000 字 / 英文 1500-2500 词 │
│ 4. 5 大控制文件全量对齐      │ 00大纲 / 01人物 / 02时序 / 03全局 / 04计划 │
│ 5. POV 视角信息隔离墙        │ 绝不串联角色隐秘，严防上帝视角穿透   │
│ 6. 配角活跃度羁绊追踪        │ 实时跟踪登场间隔，杜绝配角断崖蒸发   │
└──────────────────────────────┴──────────────────────────────┘
```

## 5 大控制文件体系

在小说项目的根目录下，系统维护着严密的 5 大状态文件：

```text
novel-project/
├── 00-outline.md             # 全书总大纲、TODO 清单、分阶段规划与逐章 Brief
├── 01-characters.md          # 角色档案、致命缺陷、MBTI、阶段弧光进化 (Ch.xx Evolution)
├── 02-timeline.md            # 严格时序表（D+N 故事天数、时钟刻度、事件约束与冲突记录）
├── 03-global-notes.md        # 既成事实基石、POV 知识边界墙、配角活跃度追踪表
├── 04-generation-plan.json   # 机器可读的章节元数据与进度计划 (状态、字数、重试记录)
├── chapter-01.md             # 章节正文 (标题 + *(POV: 角色名)*)
├── chapter-01-notes.md       # 章节备忘 (核心推进、新确立事实、伏笔、下章接力点)
└── ...
```

## 极简四阶段流水线

1. **Phase 0: 路由与断点续写**
   - 自动扫描 5 大控制文件，识别已有章节与最后一章 notes，实现秒级无缝断点续写。
2. **Phase 1: 极简意图吸收 (Lean Intake)**
   - 拒绝 20 个文学套话的繁琐审问。若用户已有大纲，直接提取题材、主线冲突、视角规则与篇幅。
3. **Phase 2: 建立 5 大控制基石**
   - 快速生成 `00-outline.md` 至 `04-generation-plan.json`，简明摘要向用户确认。
4. **Phase 3: 自主高效章节循环 (Autonomous Loop)**
   - **Step 1 Pre-Flight**：读本章 Brief + 读上章 Notes + 核对 POV 边界与配角预警。
   - **Step 2 正文 Drafting**：写足字数底线，保持自然对话与真实张力。
   - **Step 3 提炼 Notes**：沉淀核心事实、新确立事实、下章接力点。
   - **Step 4 5 文件对齐 + EPUB 导出**：自动同步 5 大状态文件，调用 `scripts/export_epub.py` 导出至桌面。
   - **Step 5 自动推进**：循环往复，无需频繁打扰用户。

## 实战案例检验：The Transfer Kid

- **作品定位**：28 章全本英文青少年写实小说（Slice of Life / Realistic YA）。
- **实战数据**：
  - 28 个章节全部达成 1500–2500 英文词，总篇幅逾 5 万词。
  - 实现了 Justin（主视角）、Marcus（第二视角）、Zack（第三视角）多 POV 轮转。
  - 成功依靠 **POV 知识边界墙** 控制了复杂的“电话号码秘密”、“伴侣身世真相”与“食堂出拳误解”，全程无一处上帝视角漏洞。
  - 所有 28 章均自动生成 EPUB 存放于 `~/Desktop/The Transfer kid/`。

## 脚本工具箱 (`scripts/`)

- **`scripts/export_epub.py`**：
  - 自动化 EPUB 导出工具，支持单章导出或全书批量打包，内置精美排版 CSS，具备 `ebooklib` 与 `pandoc` 双通道容灾。
  ```bash
  # 导出单章到桌面
  python3 scripts/export_epub.py /path/to/chapter-01.md --desktop --lang zh

  # 导出全书到桌面对应项目目录
  python3 scripts/export_epub.py /path/to/novel-project --desktop --lang en
  ```
- **`scripts/check_chapter_wordcount.py`**：
  - 精确统计汉字字数与英文词数，辅助字数基线把控。
